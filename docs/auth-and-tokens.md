# 登录与访问令牌 功能清单（产品视角）

> 登录与访问令牌让用户安全地进入 Multica 并在不同场景下访问自己的数据：
> **用邮箱验证码登录**拿到一个会话、**会话过期可以自动续期**、
> 以及为 CLI / 脚本 / 自动化生成的**长期访问令牌**。整个领域由三部分组成——
> **邮箱验证码登录**、**会话令牌（含续期与登出）**、以及**个人访问令牌与 daemon 令牌**。

这是一份自顶向下、面向用户能力的功能清单，用来核对产品功能是否齐全。

## 1. 邮箱验证码登录

- [ ] 用户只需输入邮箱即可登录，无需事先注册、无需设置密码。
- [ ] 系统向该邮箱发送一个 6 位数字验证码。
- [ ] 验证码有有效期，超时后自动失效，需要重新获取。
- [ ] 用户输入邮箱与正确的验证码后即完成登录。
- [ ] 验证码是一次性的：用过之后立刻作废，不能被重复使用。
- [ ] 如果用户多次请求验证码，以最近一次发送的有效验证码为准。
- [ ] 验证码错误或已过期时，登录被拒绝并提示重新获取。

## 2. 首次登录自动建用户

- [ ] 当一个从未登录过的邮箱完成验证码登录时，系统自动为它创建一个用户，无需单独的注册流程。
- [ ] 新用户会自动获得一个默认显示名（取自邮箱地址）。
- [ ] 同一个邮箱再次登录时，自动识别为同一个用户，不会重复创建账号。

## 3. 会话与自动续期

- [ ] 登录成功后，用户获得一个用于日常访问的会话凭证。
- [ ] 会话凭证有有效期，过期后需要续期或重新登录。
- [ ] 系统同时提供一个续期凭证，可在会话过期前/后换取新的会话，而不必重新走邮箱验证码流程。
- [ ] 续期凭证本身也有较长但有限的有效期，过期后必须重新用邮箱验证码登录。
- [ ] 每次续期都会刷新出一对全新的凭证，旧的续期凭证随即作废（一次性使用）。
- [ ] 用户可以主动登出，登出后对应的续期凭证立即失效。

## 4. 个人访问令牌（CLI / API 使用）

- [ ] 用户可以为自己创建个人访问令牌（PAT），用于在命令行工具、脚本或第三方集成中代表自己访问。
- [ ] 个人访问令牌带有可识别的 `mul_` 前缀，便于人和系统一眼区分它属于哪类凭证。
- [ ] 创建令牌时必须给它起一个名字，便于日后辨认用途。
- [ ] 用户可以为令牌设置一个可选的有效天数；不设置则视为长期有效。
- [ ] 令牌的明文只在创建时返回一次，之后系统只保留它的不可逆摘要，用户需自行妥善保存。
- [ ] 用户可以查看自己已创建的、仍然有效的令牌列表。
- [ ] 用户可以随时吊销自己的某个令牌，吊销后它立即失效。
- [ ] 已吊销或已过期的令牌无法再用于访问。
- [ ] 系统会记录令牌最近一次被使用的时间，便于用户判断它是否还在被使用。
- [ ] 个人访问令牌与邮箱登录得到的会话享有同等的访问能力，可在需要登录的接口上互换使用。

## 5. Daemon 令牌（本地 daemon 使用）

- [ ] 系统支持一类专供本地 daemon 使用的访问令牌，用于让本地 agent 运行时连接到平台。
- [ ] daemon 令牌带有可识别的 `mdt_` 前缀，与个人访问令牌区分开。
- [ ] daemon 走独立的认证通道，与用户的会话登录互不影响。

## 6. 凭证安全

- [ ] 所有长期凭证（续期凭证、个人访问令牌、daemon 令牌）都以不可逆摘要的形式保存，平台不会留存明文。
- [ ] 验证码、续期凭证、访问令牌都带有效期，避免无限期有效。
- [ ] 续期凭证一经使用即轮换，降低被重放利用的风险。
- [ ] 令牌的前缀设计让用户和工具能直观分辨凭证类型，避免误用。

## 7. 权限与 workspace 隔离

- [ ] 需要登录的功能都要求携带有效凭证（会话或个人访问令牌），否则一律拒绝访问。
- [ ] 个人访问令牌只属于创建它的用户，代表该用户的身份与权限。
- [ ] 用户只能查看、吊销自己名下的令牌，无法看到或操作他人的令牌。
- [ ] 用户的数据按 workspace 隔离：访问 workspace 内的资源时，必须指明所属 workspace。
- [ ] 只有该 workspace 的成员才能访问其中的资源；非成员会被拒绝。
- [ ] 同一个登录身份可以归属于多个 workspace，并在它们之间按成员身份分别获得相应访问权限。
